# factorio-forge

Генерация чертежей Factorio по описанию — под конкретный сейв, его сборку модов и
сложившийся стиль постройки.

[English version](README.md)

Основной способ работы — через [Claude Code](https://claude.com/claude-code):
[скилл](skill/factorio-forge/SKILL.md) из этого репозитория объясняет Claude,
как превратить запрос в план, собрать его этими инструментами, прочитать их
проверки и выдать готовый чертёж. Сами инструменты — обычная программа для
командной строки, и без Claude они тоже работают.

## Статус

Версия 0.1.0, один разработчик, проверялось на Windows с Factorio 2.0. Ниже —
то, что есть сейчас, а не планы.

**Работает и покрыто тестами** (`python -m pytest`, около 440 тестов):

- **Профили из сейва** — набор модов читается из заголовка файла сохранения;
  у каждого профиля своя папка модов из жёстких ссылок на архивы (или копий,
  если профили на другом диске, см. [Где что хранится](#где-что-хранится));
  более новые версии модов берутся и записываются, более старые или
  отсутствующие — отказ (`create-profile`, `activate-profile`, `list-profiles`,
  [docs/profiles.ru.md](docs/profiles.ru.md)).
- **Извлечение игровых данных** через
  [форк factorio-draftsman](https://github.com/Fatoom333/factorio-draftsman/tree/main-forge),
  который прогоняет настоящую Lua-стадию данных игры по модам профиля.
  Извлечению нужна установленная игра, поэтому автоматические тесты его не
  запускают; оно отработало на сейве с Krastorio 2 и на сейве Space Age с 42
  модами.
- **Отрисовка** — строка чертежа в виде одной самодостаточной HTML-страницы
  (`render`, [docs/rendering.ru.md](docs/rendering.ru.md)).
- **Проверка** — что выглядит неправильно в чертеже, без изменений в нём
  (`check`, [docs/checking.ru.md](docs/checking.ru.md)). Спаривание подземных
  лент сверено со 144 подземками, чьих партнёров записала запущенная игра.
- **Разбор запроса** — слова игрока превращаются в имена прототипов (сленг,
  названия в этой сборке, названия базовой игры), сообщается, что ещё не
  открыто, и перечисляются вопросы, на которые может ответить только игрок
  (`find`, `review`, [docs/request.ru.md](docs/request.ru.md)).
- **Подсчёт станков** — сколько станков на каждый рецепт для заданной
  скорости, с учётом исследованной продуктивности (печатает `review`). Станки —
  самые быстрые из доступных игроку, а без выгрузки самые базовые, с вопросом
  про более быстрые; станок, которому нужно топливо или тепло, отмечается.
- **Раскладка рядов** — ряды станков с лентами, манипуляторами, столбами и
  трубами, сколько станков ряд способен прокормить, зеркальные, повторённые и
  повёрнутые блоки (`options`, `build`, [docs/layout.ru.md](docs/layout.ru.md)).
  Так собрана каждая форма рецепта в профиле Krastorio 2 (63 формы).
- **Прокладка между портами блоков** — ленты и трубы от порта одного блока к
  порту другого, с подземными лентами и подземными трубами, по правилам игры
  (без бокового подвода, без касания трубы с другой жидкостью, без подземки,
  перехватывающей чужую пару) ([docs/layout.ru.md](docs/layout.ru.md)).
- **Выгрузка мода-компаньона** — то, что знает только запущенная игра
  (исследования, бонусы, стартовые настройки), читается из выгрузки
  [мода-компаньона](#мод-компаньон) и используется, только если её набор
  модов совпадает с профилем.
- **Стиль постройки**, измеренный по вашим эталонным чертежам
  (`measure-style`, `show-style`).

**Работает, но в игре ещё не подтверждено:**

- Проложенная пара подземных лент или подземных труб ровно на предельной
  дальности. Дальность берётся из прототипа; спаривает ли игра концы на этом
  расстоянии так же, ещё не проверяли.
- Поворот ленты сразу после выхода подземки. Сохраняет ли такой поворот обе
  дорожки, не подтверждено, поэтому прокладчик его не строит: поворачивает
  только после обычной ленты ([docs/layout.ru.md](docs/layout.ru.md)).

**Чего нет:**

- Разделители, слияния и балансиры между блоками; один источник на несколько
  получателей; обмен дорожек; подключение в середину ленты. Это ставится в
  плане вручную, и те же проверки идут и по нему.
- Рельеф карты: вода, скалы, руда и существующая база не считаются
  препятствиями, если вы сами не зарезервировали эти клетки.
- Поезда: ни станций, ни рельсов, ни поездных блоков.
- Генераторы целых блоков (готовая колонна плавки, блок науки). Инструменты
  строят ряды и прокладывают пути между ними; какие блоки нужны, решаете вы
  или Claude.
- Модули и маяки как сущности: бонус скорости меняет только числа.

## Что это

Большинство инструментов для чертежей выдают дизайн, правильный сам по себе, но
не привязанный ни к какой конкретной базе, — его потом всё равно приходится
переделывать руками. Задача этого проекта другая: выдать чертёж, который встаёт в
уже существующую базу как есть. Та же сетка ситиблоков, тот же шаг рельсов, тот
же тир лент, та же длина поездов и рецепты, которые действительно существуют в
данной сборке модов.

Для этого на каждый сейв заводится **профиль**: набор модов, игровые данные в том
виде, в каком их разрешает именно эта сборка, и стиль постройки, измеренный по
чертежам, которые в базе уже используются. Генерация идёт внутри соглашений
профиля.

## Как устроено

- **Набор модов сейва** читается из заголовка самого файла сохранения, без
  запуска игры. Дальше заголовка формат не разбирается: остальное — внутреннее
  представление Factorio, и бороться с ним не стоит.
- **Строки чертежей, данные о сущностях и коллизии** берутся из
  [`factorio-draftsman`](https://github.com/redruin1/factorio-draftsman) —
  библиотека прогоняет настоящий Lua data lifecycle Factorio по установленным
  модам. Взаимодействия модов разрешаются правилами самой игры, а не угадываются.
- **База и состояние исследований** выгружаются небольшим модом-компаньоном
  прямо из игры, где парсером выступает сама игра.
- **Стиль постройки** измеряется по эталонным чертежам, а не выспрашивается
  анкетой, и хранится вместе с профилем.
- **Предпочтения и поправки** копятся в `notes.md` профиля — вашими словами — и
  перечитываются при проектировании.

## Требования

- Установленная Factorio 2.0 (любая сборка модов, Space Age по желанию)
- Python 3.10 или новее (проверено на 3.12). В Windows — установщик с
  [python.org](https://www.python.org/downloads/windows/): он ставит и
  запускатель `py`, который используется ниже.
- Git: `pip` скачивает форк draftsman с GitHub
- [Claude Code](https://claude.com/claude-code) — для скилла (по желанию)

## Установка

Папка с репозиторием может лежать где угодно: скиллу и командам нужен только
путь к ней.

**Windows (PowerShell):**

```powershell
git clone https://github.com/Fatoom333/factorio-forge
cd factorio-forge
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\factorio-forge.exe paths
```

`py -3` берёт самый новый установленный Python 3, и он должен быть 3.10 или
новее. `py -0p` показывает установленные версии и где они лежат; чтобы взять
конкретную, назовите её: `py -3.11 -m venv .venv`.

Команды вызывают программы окружения по пути, поэтому активировать ничего не
нужно. Чтобы писать просто `factorio-forge`, активируйте окружение командой
`.\.venv\Scripts\Activate.ps1`; если PowerShell не даёт запускать скрипты,
один раз разрешите их для своего пользователя:
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

**Linux и macOS:**

```bash
git clone https://github.com/Fatoom333/factorio-forge
cd factorio-forge
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
.venv/bin/factorio-forge paths
```

`python3 --version` должен показать 3.10 или новее. Если версия старше,
назовите более новую из установленных: `python3.12 -m venv .venv`.

> **Примечание.** Это ставит `factorio-draftsman` из
> [форка](https://github.com/Fatoom333/factorio-draftsman/tree/main-forge), а не
> с PyPI. Ни одна выпущенная версия не умеет извлекать игровые данные для тех
> сборок, ради которых существует проект; форк — это апстримный `main` плюс три
> исправления, заведённые в апстриме, и извлечение ресурсов, астероидных
> кусков и поверхностей. Подробности — в
> [docs/draftsman-notes.ru.md](docs/draftsman-notes.ru.md) и
> [FORK.md](https://github.com/Fatoom333/factorio-draftsman/blob/main-forge/FORK.md).

`paths` показывает, где найдены игра, её сейвы и моды. Все пути определяются
автоматически, в первую очередь по тем, что Factorio сама записала в свой
последний лог. Это работает для библиотек Steam на любом диске, для
standalone-установок и на всех трёх платформах. Настраивать вручную ничего не
требуется, если определение не сорвалось. Если игра не нашлась, запустите
Factorio один раз, чтобы она записала лог, или задайте `FACTORIO_PATH` (см.
[Где что хранится](#где-что-хранится)).

Рядом с каждым путём, который `paths` нашла сама, она пишет, откуда он взят:
из переменной окружения, из файла конфига, из стандартного места для этой
системы или из лога игры — с датой этого лога. Если папок с данными игры две
(например, одна осталась от прежней установки) и выбрана не та, старая дата
это выдаст; задайте `FACTORIO_USER_DIR` с нужной папкой. Если лог в выбранной
папке говорит, что игра теперь пишет в другое место, `paths` сообщит и об этом.

`render` и `check` работают сразу — по данным базовой игры, которые идут с
draftsman. Для модов сделайте из сейва профиль и активируйте его (ниже — просто
`factorio-forge`; в Windows без активации это
`.\.venv\Scripts\factorio-forge.exe`):

```powershell
factorio-forge create-profile "My save"
factorio-forge activate-profile my-save
```

`create-profile` принимает имя сейва, как его показывает игра, или путь к
`.zip` и печатает имя профиля и готовую строку `activate-profile`. Она
называет каждый мод, который не удалось просто слинковать, и объясняет почему:
у перепакованного в архиве был мусор от macOS (папка `__MACOSX`),
скопированные лежат на другом диске. Все моды
сейва должны лежать в папке модов игры. Активация профиля подменяет игровые
данные у draftsman, установленного в этом окружении; подробности — в
[docs/profiles.ru.md](docs/profiles.ru.md).

## Скилл для Claude

Скилл — это [skill/factorio-forge/SKILL.md](skill/factorio-forge/SKILL.md).
Личные скиллы Claude Code читает из `~/.claude/skills/` (в Windows —
`%USERPROFILE%\.claude\skills\`). Поставьте туда ссылку на папку скилла, чтобы
`git pull` её обновлял, или скопируйте её.

**Windows (PowerShell), из папки `factorio-forge`:**

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.claude\skills" | Out-Null
New-Item -ItemType Junction -Path "$env:USERPROFILE\.claude\skills\factorio-forge" -Target "$PWD\skill\factorio-forge"
```

Для junction права администратора не нужны. Скопировать вместо ссылки:
`Copy-Item -Recurse skill\factorio-forge "$env:USERPROFILE\.claude\skills\"`.

**Linux и macOS, из папки `factorio-forge`:**

```bash
mkdir -p ~/.claude/skills
ln -s "$PWD/skill/factorio-forge" ~/.claude/skills/factorio-forge
```

Скопировать вместо ссылки: `cp -r skill/factorio-forge ~/.claude/skills/`.

Скилл запускает инструменты питоном из этой папки
(`.venv\Scripts\python.exe -m factorio_forge.cli` в Windows,
`.venv/bin/python -m factorio_forge.cli` в остальных системах), поэтому Claude
должен знать, где она лежит. Запускайте Claude Code в папке `factorio-forge`
или назовите ему путь к ней в разговоре; если скилл подключён ссылкой, а не
копией, Claude найдёт папку и по ссылке. Дальше просите чертёж своими словами,
например «блок на 2 батареи в секунду для моего сейва с Krastorio».

## Мод-компаньон

То, что знает только запущенная игра, — что исследовано, какие бонусы это
дало, точные стартовые настройки — выгружает небольшой мод
[factorio-forge-companion](https://github.com/Fatoom333/factorio-forge-companion).
**На портале модов Factorio его пока нет**: скачайте `.zip` со страницы
[релизов](https://github.com/Fatoom333/factorio-forge-companion/releases),
положите в папку модов, которую `factorio-forge paths` показывает как
`mods_dir`, и включите его в игре. Выгрузку исследований инструменты читают
начиная с версии 0.7.0.

Какая версия стоит, видно в меню «Моды» в игре или по
`factorio-forge-companion_<версия>.zip` с самой большой версией в папке модов:
если архивов несколько, игра загружает самый новый, так что старые можно не
удалять.

В сейве наберите в консоли `/forge-export` или нажмите Export в окне мода. Без
выгрузки инструменты тоже работают, но тиры спрашивают, а не знают, и считают,
что манипулятор берёт по одному предмету.

Выгружать можно до `create-profile` или после. Выгрузка — один файл, каждая
новая его заменяет, и инструменты читают из него исследования и бонусы при
каждом запуске, если набор модов в нём ровно тот же, что у активного профиля;
после выгрузки из другого сейва выгрузите ещё раз из этого. Только стартовые
настройки `create-profile` берёт один раз: из подходящей выгрузки, если она
есть, а иначе из текущего `mod-settings.dat` игры — он такой же, если вы не
меняли стартовые настройки с тех пор, как играли в этот сейв. `create-profile`
пишет, что именно взяла; чтобы перейти на выгрузку, выгрузите и запустите её
ещё раз с `--force` (заметки и эталонные чертежи сохранятся).

## Отрисовка чертежа

Всё, что уже является строкой чертежа, можно посмотреть:

```bash
factorio-forge render "0eNqlk...=" -o layout.html
```

Сущности рисуются в настоящем габарите, раскрашены по семействам и помечены
направлением; при наведении видны рецепты, приоритеты и прочее. Страница —
единственный самодостаточный файл, ничего не подгружающий. Подробности в
[docs/rendering.ru.md](docs/rendering.ru.md).

## Проверка чертежа

```bash
factorio-forge check "0eNqlk...="
```

Сообщает, что выглядит неправильно — подземка без второго конца, манипулятор,
не достающий ни до чего, фильтры при выключенной фильтрации, — ничего не изменяя.
Флаг `--check` у `render` отмечает находки прямо на рисунке. Обе команды
принимают и файл со строкой. Подробности в
[docs/checking.ru.md](docs/checking.ru.md).

## Где что хранится

Код лежит в репозитории, пользовательские данные — нет.

| Что | Где |
| --- | --- |
| Профили, извлечённые игровые данные, локальный конфиг | `%APPDATA%\factorio-forge\` (Windows) |
| | `~/.local/share/factorio-forge/` (Linux) |
| | `~/Library/Application Support/factorio-forge/` (macOS) |

Расположение переопределяется переменной окружения `FACTORIO_FORGE_HOME`.
Расположение самой игры — переменными `FACTORIO_PATH` и `FACTORIO_USER_DIR`, хотя
обычно определяется автоматически.

Архивы модов в профиле — жёсткие ссылки на архивы из папки модов игры
(`mods_dir` в `paths`), места они не занимают. Но жёсткая ссылка не работает
между дисками: если профили и папка модов на разных дисках, архивы копируются,
и один профиль может занять сотни мегабайт (230 МБ для сейва Space Age с 42
модами); `create-profile` сообщает, сколько скопировала. Чтобы остались жёсткие
ссылки, до создания профилей укажите в `FACTORIO_FORGE_HOME` папку на том же
диске, что и папка модов, в Windows например
`setx FACTORIO_FORGE_HOME "D:\factorio-forge"`, потом откройте новый терминал
(и перезапустите Claude Code, чтобы переменную увидел и скилл). Профили,
созданные раньше, остаются в старой папке; создайте их заново.

Извлечённые игровые данные генерируются локально и никогда не коммитятся: они
зависят от версии игры и набора модов, и распространять их проект не вправе.

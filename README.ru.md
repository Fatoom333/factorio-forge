# factorio-forge

Генерация чертежей Factorio по описанию — под конкретный сейв, его сборку модов и
сложившийся стиль постройки.

[English version](README.md)

> **Статус: ранняя разработка.** Чтение сейвов, сборка профилей и извлечение
> игровых данных работают: на реальной папке из сотни сейвов собирается каждая
> найденная сборка модов. Не написано то, что собственно выдаёт чертежи — рендер,
> мод-компаньон и генераторы. По прямому назначению пользоваться пока нечем.

## Что это

Большинство инструментов для чертежей выдают дизайн, правильный сам по себе, но
не привязанный ни к какой конкретной базе, — его потом всё равно приходится
переделывать руками. Задача этого проекта другая: выдать чертёж, который встаёт в
уже существующую базу как есть. Та же сетка ситиблоков, тот же шаг рельсов, тот
же тир лент, та же длина поездов и рецепты, которые действительно существуют в
данной сборке модов.

Для этого на каждый сейв заводится **профиль**: набор модов, игровые данные в том
виде, в каком их разрешает именно эта сборка, и стиль постройки, измеренный по
чертежам, которые в базе уже используются. Генерация идёт внутри соглашений
профиля.

## Как устроено

- **Набор модов сейва** читается из заголовка самого файла сохранения, без
  запуска игры. Дальше заголовка формат не разбирается: остальное — внутреннее
  представление Factorio, и бороться с ним не стоит.
- **Строки чертежей, данные о сущностях и коллизии** берутся из
  [`factorio-draftsman`](https://github.com/redruin1/factorio-draftsman) —
  библиотека прогоняет настоящий Lua data lifecycle Factorio по установленным
  модам. Взаимодействия модов разрешаются правилами самой игры, а не угадываются.
- **База и состояние исследований** будут выгружаться небольшим модом-компаньоном
  прямо из игры, где парсером выступает сама игра. *(Ещё не написано.)*
- **Стиль постройки** измеряется по эталонным чертежам, а не выспрашивается
  анкетой. *(Ещё не написано.)*

## Требования

- Factorio 2.0 (любая сборка модов, Space Age по желанию)
- Python 3.10 или новее

## Установка

```bash
git clone https://github.com/Fatoom333/factorio-forge
cd factorio-forge
python -m venv .venv
```

Активировать окружение — `.venv\Scripts\activate` в Windows (`Activate.ps1` из
PowerShell), `source .venv/bin/activate` в Linux и macOS — затем:

```bash
pip install -e ".[dev]"
```

> **Примечание.** Это ставит `factorio-draftsman` из
> [форка](https://github.com/Fatoom333/factorio-draftsman/tree/3.3.1-forge), а не
> с PyPI. Ни одна выпущенная версия не умеет извлекать игровые данные для тех
> сборок, ради которых существует проект; форк — это апстримный 3.3.1 плюс пять
> исправлений и больше ничего, все они заведены в апстриме. Что это за
> исправления — в [docs/draftsman-notes.ru.md](docs/draftsman-notes.ru.md),
> сами патчи — в
> [FORK.md](https://github.com/Fatoom333/factorio-draftsman/blob/3.3.1-forge/FORK.md).
> После их выпуска зависимость станет обычной.

Дальше проверка того, что игра найдена:

```bash
factorio-forge paths
```

Все пути определяются автоматически, в первую очередь по тем, что Factorio сама
записала в свой последний лог. Это работает для библиотек Steam на любом диске,
для standalone-установок и на всех трёх платформах. Настраивать вручную ничего не
требуется, если определение не сорвалось.

## Где что хранится

Код лежит в репозитории, пользовательские данные — нет.

| Что | Где |
| --- | --- |
| Профили, извлечённые игровые данные, локальный конфиг | `%APPDATA%\factorio-forge\` (Windows) |
| | `~/.local/share/factorio-forge/` (Linux) |
| | `~/Library/Application Support/factorio-forge/` (macOS) |

Расположение переопределяется переменной окружения `FACTORIO_FORGE_HOME`.
Расположение самой игры — переменными `FACTORIO_PATH` и `FACTORIO_USER_DIR`, хотя
обычно определяется автоматически.

Извлечённые игровые данные генерируются локально и никогда не коммитятся: они
зависят от версии игры и набора модов, и распространять их проект не вправе.
